# Project Prompt: "Kavi Kaavya Kadambakam" (KKK) — a Quarto + Python data-driven static site

## Goal
Build a **static website** (Quarto website) whose pages are **auto-generated by a single Python script** from **two CSV files**. The site presents a browsable, searchable catalog of two linked entity types — here **Poets** and **Works** (a one-to-many relationship: each work has one author/poet). Adapt entity names freely (e.g., Authors/Books, Artists/Paintings, Chefs/Recipes).

## Tech stack
- **Python 3** with `pandas` (data) and `plotly` (chart export requires `kaleido`).
- **Quarto** website renderer (`quarto render`).
- **Bootstrap 5** components (tabs, accordions, badges, tables) + custom `styles.css`.
- All interactivity is **vanilla JS** embedded in QMD `{=html}` blocks (client-side search, sort, pagination). No server, no runtime DB.

## Inputs (source of truth — placed in the PARENT dir of the project)
The script reads:
- `../poetsfeed.csv`
- `../worksfeed.csv`

Columns used by the generator (read with `encoding="utf-8-sig"`, header whitespace stripped):

**poetsfeed.csv**
- `Poet ID`
- `Name of the Poet`
- `Time period of the Poet`
- `Life of the Poet`
- `Contribution of the poet to the Sanskrit Literature`

**worksfeed.csv**
- `Work ID`
- `Name of the Work`
- `Author` (first line is matched to a poet name)
- `Genre`
- `Summary of the work`
- `Contents of the work`
- `Uniqueness of the work`
- `Contribution to Sanskrit Literature`
- `Any other notable information`
- `Quotable Quotations`

## Architecture — one script, `generate.py`, with these responsibilities
1. **Slugify names → stems** (`slugify()` — lowercase, strip non-word, spaces→`-`), with dedup (`name`, `name-1`, `name-2`) via `assign_stems()`.
2. **Build relationship maps**: poet-name → stem; poet-stem → list of works; author → works.
3. **Generate one QMD per poet** → `poets/<stem>.qmd`. Layout = **Bootstrap tabbed card**: Overview (time period), Life, Contribution, Works (N) (list of links to work pages).
4. **Generate one QMD per work** → `works/<stem>.qmd`. Layout = **Bootstrap accordion** with sections: Author (linked), Summary, Contents, Uniqueness, Contribution & Notes (contribution + other info merged), Quotable Quotations, Genre (badge).
5. **Index/listing pages** with client-side **search + column sort + pagination** (JS generated by `generate_table_js()`):
   - `poets/index.qmd` — table: Poet ID | Name | Works(tags), default 10 rows.
   - `works/index.qmd` — table: Work ID | Work | Author | Genre, default 15 rows.
6. **Home page** `index.qmd` — description, three **value-box** stat cards (counts of Poets/Works/Genres), a **genre bar chart image** (`data/genre_chart.png`), an "Explore" link list, and an auto-scrolling **quotes marquee** built from `Quotable Quotations`.
7. **Global search** `search.qmd` — embeds all records as JSON in a `<script type="application/json">` block and filters client-side across poets + works (name, author, summary, contribution, quotes) with match highlighting. Supports `?q=` URL param.
8. **Navbar search box** `navbar-search.html` (injected via `include-in-header`) that redirects to `search.html?q=...`.
9. **Genre analytics** — `data/genre_counts.json` + horizontal bar `data/genre_chart.png` via Plotly (`write_image`, scale 2).
10. **Regenerates site scaffolding every run**: `_quarto.yml`, `about.qmd`, `styles.css`.

## Generated files (output)
```
generate.py
_quarto.yml                 # Quarto website config (navbar, theme cosmo, custom css, header include)
styles.css                  # full theme (see below)
index.qmd                   # home
about.qmd                   # about
search.qmd                  # global search
navbar-search.html          # injected navbar search
poets/index.qmd + <stem>.qmd
works/index.qmd + <stem>.qmd
data/genre_counts.json, data/genre_chart.png
home/                        # empty; reserved for extra markdown content
```
Post-render step deletes Quarto's default `_site/search.json` (custom search replaces it). `_quarto.yml` sets `search: false`.

## Text-handling details (important for correctness)
- `html_content()` — preserves newlines as `<br>`, escapes HTML, escapes Markdown special chars, and guards lines that would be parsed as Markdown blocks (headings, lists, numbers).
- `yaml_str()` — quotes/escapes titles with special chars (`:`, `#`, `[]`, etc.).
- `fold_text()` — Unicode NFD + strip combining marks for accent-insensitive search (e.g., "kalidasa" matches "Kāḷidāsa").
- Empty/`nan` values render friendly placeholders ("No information available.").

## Theme / styling (`styles.css`)
Warm "manuscript" palette via CSS variables: cream background (`#fff8ed`), maroon (`#6b0f1a`), gold accents (`#c8894a`), serif headings (Georgia), styled value-boxes, marquee animation, custom badges, rounded search inputs.

## Build & run
```
pip install pandas plotly kaleido         # deps
python generate.py                        # regenerate all QMD/HTML scaffold from CSVs
quarto render                             # build _site/
```
No package.json; no test suite. Everything is regenerated by `generate.py`, so **edit the CSVs (or `generate.py`) and re-run** — never hand-edit generated QMD files.

## Customization points for a new project
1. Replace the two feed CSVs (rename + adjust the column-name constants in `generate.py`).
2. Rename entities (Poet/Work → your two types) across templates and labels.
3. Re-theme `generate_styles_css()` (colors, fonts, site title, footer).
4. Add/remove tabs (poet pages) and accordion sections (work pages) in `generate_poet_qmd()` / `generate_work_qmd()`.
5. Adjust table columns, default page size, and searchable fields in the `*_index_qmd()` and `build_search_records()` functions.
6. Point `POETS_CSV`/`WORKS_CSV` at your new data location.
